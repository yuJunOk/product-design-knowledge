# 设计原则速查

> 常用设计原则快速参考手册

---

## 一、尼尔森十大可用性原则

### 1. 系统状态可见性（Visibility of System Status）

**原则**：系统应在合理时间内通过适当反馈，让用户了解正在发生什么。

| 应用 | 示例 |
|------|------|
| 加载状态 | 显示加载动画或进度条 |
| 操作反馈 | 按钮点击后有视觉变化 |
| 状态更新 | 消息已读/未读状态显示 |
| 位置指示 | 面包屑、步骤条显示当前位置 |

---

### 2. 系统与现实世界匹配（Match Between System and Real World）

**原则**：使用用户熟悉的语言、概念，而不是系统术语。

| 应用 | 示例 |
|------|------|
| 语言 | 用"购物车"而不是"订单容器" |
| 图标 | 垃圾桶表示删除，放大镜表示搜索 |
| 流程 | 购物流程与现实购物一致 |
| 隐喻 | 文件夹、桌面等现实隐喻 |

---

### 3. 用户控制与自由（User Control and Freedom）

**原则**：提供撤销和重做功能，让用户有退路。

| 应用 | 示例 |
|------|------|
| 撤销操作 | 删除后可恢复 |
| 返回功能 | 明显的返回按钮 |
| 取消操作 | 长流程中可退出 |
| 编辑修改 | 发布后可编辑 |

---

### 4. 一致性与标准（Consistency and Standards）

**原则**：遵循平台惯例，保持内部一致。

| 类型 | 说明 | 示例 |
|------|------|------|
| 平台一致 | 符合iOS/Android规范 | 导航位置、手势操作 |
| 内部一致 | 相同元素表现一致 | 相同按钮样式统一 |
| 行业一致 | 符合行业惯例 | 电商的购物流程 |

---

### 5. 错误预防（Error Prevention）

**原则**：在错误发生前预防，比错误提示更好。

| 应用 | 示例 |
|------|------|
| 输入限制 | 手机号输入框只接受数字 |
| 确认操作 | 删除前二次确认 |
| 默认选项 | 提供合理的默认值 |
| 防错设计 | 形状不同的插头防止插错 |

---

### 6. 识别而非回忆（Recognition Rather Than Recall）

**原则**：让用户识别而不是记忆信息。

| 应用 | 示例 |
|------|------|
| 可见选项 | 所有功能可见，不用记忆命令 |
| 历史记录 | 显示搜索历史、浏览记录 |
| 自动补全 | 输入时提供建议 |
| 最近使用 | 显示最近使用的文件 |

---

### 7. 使用的灵活性与效率（Flexibility and Efficiency of Use）

**原则**：兼顾新手和专家用户。

| 应用 | 新手 | 专家 |
|------|------|------|
| 快捷方式 | 可见的菜单操作 | 快捷键、手势 |
| 自定义 | 默认设置 | 自定义配置 |
| 批量操作 | 单个操作 | 批量选择、操作 |

---

### 8. 美学与极简设计（Aesthetic and Minimalist Design）

**原则**：界面不应包含无关或很少需要的信息。

| 应用 | 示例 |
|------|------|
| 信息层级 | 重要信息突出，次要信息弱化 |
| 留白使用 | 适当的留白减少视觉负担 |
| 删除冗余 | 删除不必要的装饰和文字 |
| 视觉清晰 | 清晰的排版和配色 |

---

### 9. 帮助用户识别、诊断和恢复错误（Help Users Recognize, Diagnose, and Recover from Errors）

**原则**：错误信息应清晰，提供解决方案。

| 应用 | 示例 |
|------|------|
| 清晰描述 | "网络连接失败"而不是"Error 404" |
| 解决方案 | 提供"重试"按钮 |
| 友好语气 | 不用技术术语，不用责备语气 |
| 预防建议 | 告诉用户如何避免 |

---

### 10. 帮助与文档（Help and Documentation）

**原则**：提供帮助文档，但最好不需要文档就能使用。

| 应用 | 示例 |
|------|------|
| 上下文帮助 | 输入框旁的提示文字 |
| 引导教程 | 首次使用的功能引导 |
| FAQ | 常见问题解答 |
| 搜索帮助 | 帮助文档可搜索 |

## 二、格式塔原理（Gestalt Principles）

### 1. 接近性（Proximity）

**原理**：距离近的物体被认为是一组。

**应用**：
- 相关功能按钮放在一起
- 表单字段按逻辑分组
- 列表项之间保持适当间距

### 2. 相似性（Similarity）

**原理**：相似的物体被认为是一组。

**应用**：
- 相同功能用相同样式
- 同级别的标题用相同字号
- 同类型的按钮颜色一致

### 3. 连续性（Continuity）

**原理**：人眼倾向于沿着平滑路径观察。

**应用**：
- 使用线条引导视线
- 步骤指示器显示流程
- 时间线设计

### 4. 闭合性（Closure）

**原理**：大脑会自动补全不完整的形状。

**应用**：
- 简洁的图标设计
- 负空间利用
- 省略号暗示更多内容

### 5. 共同命运（Common Fate）

**原理**：一起运动的物体被认为是一组。

**应用**：
- 展开/收起动画
- 批量操作时的选中状态
- 同步加载动画

### 6. 图形-背景（Figure-Ground）

**原理**：人眼能区分前景和背景。

**应用**：
- 模态弹窗的背景遮罩
- 悬浮按钮的阴影
- 重要内容的突出显示

## 三、其他重要原则

### 菲茨定律（Fitts's Law）

**原理**：移动到目标的时间与距离成正比，与目标大小成反比。

**应用**：
- 重要按钮做大一些
- 常用功能放在容易点击的位置
- 边缘和角落是"无限大"的目标

### 希克定律（Hick's Law）

**原理**：决策时间与选项数量成正比。

**应用**：
- 减少选项数量
- 使用分类减少认知负担
- 提供默认选项

### 米勒定律（Miller's Law）

**原理**：人脑短期记忆能记住7±2个信息块。

**应用**：
- 导航项不超过7个
- 分步骤展示信息
- 使用分块组织信息

### 特斯勒定律（Tesler's Law）

**原理**：复杂性守恒，只能转移不能消除。

**应用**：
- 权衡用户和系统的复杂性分配
- 核心功能简单，高级功能复杂
- 渐进式披露复杂性

### 防错原则（Poka-Yoke）

**原理**：通过设计防止错误发生。

**应用**：
- 输入格式自动校验
- 不可逆操作二次确认
- 默认安全选项

## 四、移动端特有原则

### 拇指区域（Thumb Zone）

| 区域 | 易达性 | 适合放置 |
|------|--------|----------|
| 绿色区（底部中央） | 最易达 | 核心操作 |
| 黄色区（两侧） | 较易达 | 次要操作 |
| 红色区（顶部） | 较难达 | 不常用操作 |

### 触控目标大小

- 最小触控目标：44×44px
- 推荐触控目标：48×48px
- 触控目标间距：至少8px

### 手势设计

| 手势 | 通用含义 | 使用建议 |
|------|----------|----------|
| 点击 | 选择/确认 | 最基础操作 |
| 滑动 | 浏览/切换 | 左右滑动切换Tab |
| 下拉 | 刷新 | 列表顶部下拉 |
| 上拉 | 加载更多 | 列表底部上拉 |
| 长按 | 更多选项 | 提供上下文菜单 |
| 捏合 | 缩放 | 图片/地图缩放 |

## 五、B端设计原则

### 效率优先

- 减少操作步骤
- 支持批量操作
- 提供快捷键
- 记住用户偏好

### 信息密度

- 一屏展示更多信息
- 使用表格而非卡片
- 紧凑但不拥挤
- 可自定义列显示

### 可预期性

- 操作结果可预期
- 状态变化可见
- 错误可恢复
- 数据可导出

## 六、原则冲突时的处理

### 常见冲突

| 冲突 | 场景 | 建议 |
|------|------|------|
| 简洁 vs 完整 | 删除功能还是保留 | 保留核心，隐藏次要 |
| 一致 vs 创新 | 遵循规范还是创新 | 核心流程一致，细节可创新 |
| 效率 vs 易学 | 快捷键 vs 可见菜单 | 提供多种方式 |
| 美观 vs 实用 | 极简 vs 功能完整 | 平衡，不牺牲核心功能 |

### 决策框架

```
1. 明确当前场景的核心目标
2. 识别涉及的用户类型
3. 评估各原则的重要性
4. 选择最符合当前场景的方案
5. 通过测试验证决策
```

## 七、快速检查清单

### 可用性检查

- [ ] 用户知道当前在哪
- [ ] 用户知道能做什么
- [ ] 操作后有反馈
- [ ] 可以撤销操作
- [ ] 错误提示清晰有用
- [ ] 不需要记忆太多信息

### 视觉设计检查

- [ ] 重要信息突出
- [ ] 相关元素分组
- [ ] 相似元素一致
- [ ] 留白适当
- [ ] 色彩有层次
- [ ] 字体有层级

### 交互设计检查

- [ ] 触控目标足够大
- [ ] 常用功能易达
- [ ] 手势符合习惯
- [ ] 动画自然流畅
- [ ] 状态变化可见
- [ ] 加载有反馈
