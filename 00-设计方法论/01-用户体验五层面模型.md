# 用户体验五层面模型

> 来源：《用户体验要素》Jesse James Garrett
> 用途：系统化分析任何产品的设计框架

---

## 模型概述

五层面模型是一个从抽象到具体的产品设计框架，包含五个层次：

```
┌─────────────────────────────────────┐
│  第5层 表现层 (Surface)              │  ← 视觉设计
│  用户第一眼看到的东西                 │
├─────────────────────────────────────┤
│  第4层 框架层 (Skeleton)             │  ← 界面布局
│  界面元素如何排列                     │
├─────────────────────────────────────┤
│  第3层 结构层 (Structure)            │  ← 交互设计
│  用户如何从一个地方到另一个地方       │
├─────────────────────────────────────┤
│  第2层 范围层 (Scope)                │  ← 功能规格
│  产品包含什么功能                     │
├─────────────────────────────────────┤
│  第1层 战略层 (Strategy)             │  ← 产品目标
│  为什么做这个产品                     │
└─────────────────────────────────────┘
```

---

## 各层面详解

### 第1层：战略层 (Strategy)

**核心问题**：为什么做这个产品？为谁做？

| 要素 | 说明 | 关键问题 |
|------|------|----------|
| **产品目标** | 企业/团队想通过产品获得什么 | 产品的商业目标是什么？ |
| **用户需求** | 目标用户想通过产品获得什么 | 用户是谁？他们的痛点是什么？ |

**输出物**：
- 产品定位说明
- 用户画像（Persona）
- 用户故事（User Story）

---

### 第2层：范围层 (Scope)

**核心问题**：产品包含什么功能？不包含什么？

| 要素 | 说明 | 关键问题 |
|------|------|----------|
| **功能规格** | 产品需要实现的功能清单 | 必须做哪些功能？优先级如何？ |
| **内容需求** | 产品需要展示的内容 | 需要什么内容？谁来提供？ |

**输出物**：
- 功能清单（Feature List）
- 需求优先级（MoSCoW法则）
- 内容清单

**常用工具**：
- 功能清单表格
- 用户故事地图
- Kano模型

---

### 第3层：结构层 (Structure)

**核心问题**：用户如何从一个地方到另一个地方？

| 要素 | 说明 | 关键问题 |
|------|------|----------|
| **交互设计** | 用户如何与产品互动 | 用户操作流程是什么？ |
| **信息架构** | 内容如何组织和分类 | 信息如何分组？层级关系？ |

**输出物**：
- 用户流程图（User Flow）
- 信息架构图（IA Map）
- 页面关系图

**常用工具**：
- 流程图（Flowchart）
- 卡片分类（Card Sorting）
- 站点地图（Sitemap）

---

### 第4层：框架层 (Skeleton)

**核心问题**：界面元素如何排列？

| 要素 | 说明 | 关键问题 |
|------|------|----------|
| **界面设计** | 界面元素如何布局 | 按钮放哪里？信息怎么排？ |
| **导航设计** | 用户如何在不同页面间移动 | 导航放在哪？有哪些入口？ |
| **信息设计** | 信息如何呈现 | 哪些信息突出显示？ |

**输出物**：
- 线框图（Wireframe）
- 原型图（Prototype）
- 导航设计文档

**常用工具**：
- 纸笔草图
- Axure RP / Figma / Sketch
- Balsamiq

---

### 第5层：表现层 (Surface)

**核心问题**：产品看起来是什么样的？

| 要素 | 说明 | 关键问题 |
|------|------|----------|
| **视觉设计** | 产品的视觉呈现 | 用什么颜色？字体？风格？ |
| **品牌传达** | 如何体现品牌调性 | 设计是否符合品牌定位？ |

**输出物**：
- 视觉稿（Mockup）
- UI设计规范
- 设计系统（Design System）

**常用工具**：
- Figma / Sketch / Adobe XD
- 设计规范文档

---

## 使用方法

### 自上而下设计（从0到1）

适用于新产品设计，从战略到表现逐层细化：

```
战略层 → 范围层 → 结构层 → 框架层 → 表现层
(为什么)  (做什么)  (怎么做)  (布局)   (视觉)
```

**步骤**：
1. 明确产品目标和用户需求
2. 确定功能范围和内容需求
3. 设计信息架构和用户流程
4. 绘制线框图和原型
5. 完成视觉设计

### 自下而上分析（分析现有产品）

适用于竞品分析，从表现反推战略：

```
表现层 → 框架层 → 结构层 → 范围层 → 战略层
(看到什么) (怎么排) (怎么走) (有什么) (为什么)
```

**步骤**：
1. 观察界面视觉设计
2. 分析界面布局和导航
3. 梳理信息架构和流程
4. 整理功能清单
5. 推导产品目标和用户定位

## 不同平台的侧重点

### 移动端应用

| 层面 | 侧重点 |
|------|--------|
| 战略层 | 场景碎片化，解决即时需求 |
| 范围层 | 功能精简，专注核心场景 |
| 结构层 | 层级浅，3步内完成任务 |
| 框架层 | 触摸优先，按钮大，留白多 |
| 表现层 | 视觉冲击，品牌感强 |

### PC端后台系统

| 层面 | 侧重点 |
|------|--------|
| 战略层 | 提高工作效率，降低操作成本 |
| 范围层 | 功能完整，支持复杂操作 |
| 结构层 | 层级深，模块多，权限复杂 |
| 框架层 | 信息密度高，表格、筛选、批量操作 |
| 表现层 | 简洁专业，数据可视化 |

### 内容型网站

| 层面 | 侧重点 |
|------|--------|
| 战略层 | 内容分发效率，用户停留时长 |
| 范围层 | 内容类型、推荐算法、搜索功能 |
| 结构层 | 分类体系、标签系统、内容关联 |
| 框架层 | 阅读体验、内容流、广告位 |
| 表现层 | 突出内容、阅读舒适度 |

## 常见错误

| 错误 | 说明 | 正确做法 |
|------|------|----------|
| 跳过战略层直接画界面 | 不知道为什么要做这个功能 | 先明确目标和用户 |
| 范围层功能堆砌 | 什么都想做，没有优先级 | 用MVP思维，先做核心功能 |
| 结构层流程复杂 | 用户需要很多步才能完成任务 | 简化流程，减少点击次数 |
| 框架层布局混乱 | 信息没有主次，用户找不到重点 | 建立视觉层级，突出核心 |
| 表现层过度设计 | 视觉效果干扰功能使用 | 形式追随功能，视觉服务于内容 |
