# 目标导向设计

> 来源：《About Face 4：交互设计精髓》Alan Cooper
> 用途：以用户目标为核心的设计方法

---

## 核心概念

### 什么是目标导向设计

目标导向设计（Goal-Directed Design）是一种以**用户目标**为核心的交互设计方法，强调：

- 设计应帮助用户实现目标，而非仅仅完成任务
- 通过研究理解用户的真实需求
- 用人物角色（Persona）作为设计决策的基准

### 三个核心要素

```
┌─────────────────────────────────────┐
│           目标导向设计               │
├─────────────────────────────────────┤
│  ┌─────────┐ ┌─────────┐ ┌────────┐ │
│  │ 人物角色 │ │  目标   │ │  场景  │ │
│  │ Persona │ │  Goal   │ │Scenario│ │
│  └─────────┘ └─────────┘ └────────┘ │
└─────────────────────────────────────┘
```

## 人物角色（Persona）

### 什么是人物角色

人物角色是基于用户研究创建的**虚构用户模型**，代表一类真实用户群体。

**不是**：
- ❌ 真实用户的简单描述
- ❌ 市场细分人群
- ❌ 用户需求的罗列

**而是**：
- ✅ 基于研究的用户行为模式总结
- ✅ 帮助设计决策的工具
- ✅ 具体、可感知的用户形象

### 人物角色的构成

| 维度 | 内容 | 说明 |
|------|------|------|
| **基本信息** | 姓名、年龄、职业、照片 | 让角色具象化 |
| **人口属性** | 收入、地域、家庭状况 | 背景信息 |
| **行为特征** | 使用习惯、技术熟练度 | 关键行为模式 |
| **目标和动机** | 使用产品的目的 | 设计的核心依据 |
| **痛点和挫折** | 当前面临的问题 | 设计机会点 |
| **引用语录** | 代表性言论 | 体现用户态度 |

### 人物角色示例

#### 主要人物角色：王小明

| 属性 | 描述 |
|------|------|
| **照片** | [照片] |
| **基本信息** | 男，28岁，互联网公司产品经理 |
| **人口属性** | 月收入15k，一线城市，未婚 |
| **行为特征** | 每天使用手机4+小时，熟悉各类App，追求效率 |
| **目标** | 快速获取信息，高效完成任务 |
| **痛点** | 操作步骤太多，等待时间长，信息找不到 |
| **语录** | "别让我等，别让我想，别让我烦" |

### 人物角色的创建步骤

```
第1步：用户研究
    ↓ 收集数据
第2步：行为模式分析
    ↓ 识别行为变量
第3步：映射访谈对象
    ↓ 归类分组
第4步：确定人物角色类型
    ↓ 优先级排序
第5步：完善人物角色细节
    ↓ 验证和迭代
第6步：应用人物角色指导设计
```

### 人物角色类型

| 类型 | 说明 | 数量 |
|------|------|------|
| **主要人物角色** | 产品设计的主要服务对象 | 1-2个 |
| **次要人物角色** | 次要用户群体 | 2-3个 |
| **补充人物角色** | 边缘用户，满足即可 | 少量 |
| **负面人物角色** | 非目标用户，明确排除 | 1-2个 |

## 目标（Goal）

### 目标的层次

| 层次 | 说明 | 示例 |
|------|------|------|
| **人生目标** | 长期的人生追求 | 成为行业专家 |
| **最终目标** | 使用产品的最终目的 | 买到合适的商品 |
| **阶段性目标** | 完成任务的目标 | 找到商品信息 |
| **任务目标** | 具体操作的目标 | 搜索关键词 |

### 目标 vs 任务

| 对比 | 目标 | 任务 |
|------|------|------|
| **本质** | 用户想要达成的结果 | 达成目标的具体操作 |
| **稳定性** | 稳定，不易改变 | 随技术变化 |
| **设计依据** | ✅ 应该基于目标设计 | ❌ 不应只基于任务设计 |
| **示例** | 买到合适的手机 | 点击筛选按钮 |

### 用户目标的三种类型

| 类型 | 说明 | 设计关注点 |
|------|------|------------|
| **体验目标** | 用户想要的感觉 | 情感化设计、品牌感知 |
| **最终目标** | 用户想要的结果 | 功能完整性、效率 |
| **人生目标** | 用户的自我实现 | 长期价值、成长体系 |

## 场景（Scenario）

### 什么是场景

场景是描述**人物角色如何使用产品达成目标**的故事，包含：
- 具体情境（时间、地点、环境）
- 人物角色的行为和决策
- 与产品的交互过程

### 场景剧本的类型

| 类型 | 阶段 | 用途 |
|------|------|------|
| **情境场景** | 早期 | 理解用户需求，无具体界面 |
| **关键线路径** | 中期 | 定义功能和流程 |
| **验证场景** | 后期 | 验证设计方案 |

### 情境场景模板

```
【场景标题】：（名称）

【人物角色】：（使用场景的角色）

【情境】：
- 时间：
- 地点：
- 环境：
- 前置条件：

【目标】：（角色想要达成什么）

【流程】：
1. （角色做了什么）
2. （角色看到了什么）
3. （角色如何决策）
4. ...

【结果】：（是否达成目标）

【情绪变化】：😊 → 😐 → 😟 → 😊

【设计机会】：（可以改进的地方）
```

### 场景示例

**场景：下班路上点外卖**

| 要素 | 描述 |
|------|------|
| **人物角色** | 王小明（上班族） |
| **情境** | 周五晚上6点，地铁上，手机信号一般 |
| **目标** | 30分钟内吃到晚饭 |
| **流程** | 1. 打开App<br>2. 浏览推荐商家<br>3. 选择常点的套餐<br>4. 确认地址下单<br>5. 查看配送进度 |
| **情绪** | 😊期待 → 😐选择 → 😊下单 → 😟等待 → 😊收到 |
| **机会点** | 信号不好时如何优化加载？如何减少选择困难？ |

## 设计流程

### 目标导向设计的6个阶段

```
┌─────────────────────────────────────────────────────┐
│  第1阶段：研究                                       │
│  定性研究、定量研究、利益相关者访谈                    │
├─────────────────────────────────────────────────────┤
│  第2阶段：建模                                       │
│  用户建模（人物角色）、工作流建模                      │
├─────────────────────────────────────────────────────┤
│  第3阶段：定义需求                                    │
│  情境场景、需求定义                                   │
├─────────────────────────────────────────────────────┤
│  第4阶段：定义框架                                    │
│  对象关系、关键线路径、验证场景                        │
├─────────────────────────────────────────────────────┤
│  第5阶段：细化                                        │
│  详细设计、交互设计、视觉设计                          │
├─────────────────────────────────────────────────────┤
│  第6阶段：支持                                        │
│  设计验证、开发支持、迭代优化                          │
└─────────────────────────────────────────────────────┘
```

### 各阶段交付物

| 阶段 | 交付物 |
|------|--------|
| 研究 | 用户研究报告、利益相关者访谈记录 |
| 建模 | 人物角色文档、工作流图 |
| 定义需求 | 情境场景剧本、需求列表 |
| 定义框架 | 信息架构、关键线路径剧本 |
| 细化 | 线框图、原型、视觉稿 |
| 支持 | 设计规范、走查报告 |

## 实践方法

### 创建人物角色清单

- [ ] 完成用户访谈（至少5-8人）
- [ ] 整理访谈记录，提取行为变量
- [ ] 识别行为模式，分组归类
- [ ] 确定主要、次要、补充人物角色
- [ ] 为每个人物角色编写详细描述
- [ ] 添加照片和引用语录
- [ ] 团队评审和确认
- [ ] 在设计决策中应用

### 编写场景剧本清单

- [ ] 确定核心人物角色
- [ ] 选择关键目标
- [ ] 设定具体情境
- [ ] 描述完整流程
- [ ] 标注情绪变化
- [ ] 识别设计机会
- [ ] 与团队分享讨论

## 常见错误

| 错误 | 说明 | 正确做法 |
|------|------|----------|
| 人物角色太泛 | 描述过于笼统，没有针对性 | 基于真实数据，具体细节 |
| 人物角色太多 | 创建太多角色，失去焦点 | 聚焦1-2个主要角色 |
| 目标不明确 | 混淆目标和任务 | 多问"为什么"找到真实目标 |
| 场景不具体 | 场景过于抽象 | 设定具体时间地点情境 |
| 创建后不用 | 人物角色束之高阁 | 在设计评审时引用角色 |

## 与其他方法的关系

| 方法 | 关系 | 区别 |
|------|------|------|
| 用户体验五层面 | 目标导向设计是五层面中"战略层"的具体方法 | 五层面更全面，目标导向更聚焦用户 |
| 用户故事 | 场景剧本可以转化为用户故事 | 场景更关注情境，用户故事更简洁 |
| 用户画像 | 人物角色是更具体、可操作的用户画像 | 画像偏描述，角色偏设计决策 |
