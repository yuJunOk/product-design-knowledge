# 交互设计四策略

> 来源：《简约至上：交互式设计四策略》Giles Colborne
> 用途：简化复杂功能的设计方法

---

## 核心概念

### 什么是简约至上

简约至上的核心思想：**删除不必要的，组织要提供的，隐藏非核心的，转移复杂性的**。

四个策略按优先级排序：

```
┌─────────────────────────────────────┐
│  第1策略：删除（Remove）              │
│  去掉所有不必要的功能                  │
├─────────────────────────────────────┤
│  第2策略：组织（Organize）            │
│  将功能按有意义的方式分组              │
├─────────────────────────────────────┤
│  第3策略：隐藏（Hide）                │
│  将不常用功能隐藏起来                  │
├─────────────────────────────────────┤
│  第4策略：转移（Transfer）            │
│  将复杂性转移到合适的地方              │
└─────────────────────────────────────┘
```

---

## 策略一：删除（Remove）

### 核心原则

**删除是简化设计的最直接方式。**

> "完美的设计不是没有什么可以添加，而是没有什么可以删减。" —— 安托万·德·圣埃克苏佩里

### 删除什么

| 删除对象 | 说明 | 示例 |
|----------|------|------|
| **多余的功能** | 没人用的功能 | 产品中使用率<5%的功能 |
| **冗余的文字** | 不必要的说明 | "请输入"标签（占位符已说明） |
| **多余的选项** | 过多的选择 | 从20个选项减到3个 |
| **视觉干扰** | 装饰性元素 | 过度的阴影、渐变 |
| **重复的入口** | 多个地方做同一件事 | 合并相似功能入口 |

### 删除决策方法

**功能删除检查清单**：

- [ ] 这个功能有多少用户使用？
- [ ] 这个功能对用户有多重要？
- [ ] 删除后会影响核心流程吗？
- [ ] 是否有替代方案？
- [ ] 维护这个功能成本高吗？

**如果答案都是负面的，考虑删除。**

### 删除的误区

| 误区 | 说明 | 正确做法 |
|------|------|----------|
| 删除核心功能 | 为了简化而删除必要功能 | 保留核心，删除边缘 |
| 一次性删除太多 | 用户无法适应 | 渐进式删除，观察反馈 |
| 只删除不替代 | 删除后没有解决方案 | 提供替代路径 |

## 策略二：组织（Organize）

### 核心原则

**通过有意义的分组，降低认知负担。**

### 组织方法

#### 1. 分块（Chunking）

将信息分成小块，便于理解和记忆。

```
错误：
电话号码：13812345678

正确：
电话号码：138 1234 5678
```

#### 2. 分类（Categorizing）

按逻辑关系将功能分组。

| 组织方式 | 适用场景 | 示例 |
|----------|----------|------|
| 按主题 | 内容型产品 | 新闻按频道分类 |
| 按流程 | 任务型产品 | 购物按浏览-下单-支付 |
| 按用户 | 多角色产品 | B端按管理员/普通用户 |
| 按频率 | 功能型产品 | 常用功能放前面 |
| 按时间 | 时间线产品 | 消息按今天/昨天/更早 |

#### 3. 层级（Hierarchy）

建立清晰的层级关系。

```
一级：最重要的信息/操作
  └─ 二级：次要信息/操作
       └─ 三级：详细信息/操作
```

#### 4. 布局（Layout）

利用空间位置组织信息。

| 位置 | 用户注意力 | 适合放置 |
|------|------------|----------|
| 左上 | 最高 | 核心内容、品牌 |
| 右上 | 高 | 操作按钮 |
| 左下 | 中 | 辅助信息 |
| 右下 | 低 | 次要操作 |
| 中部 | 中 | 主要内容 |

### 组织原则

- **7±2原则**：一组信息不超过9个，最好5-7个
- **相关性原则**：相关的内容放在一起
- **一致性原则**：相同类型的内容用相同方式组织

## 策略三：隐藏（Hide）

### 核心原则

**将不常用功能隐藏，保持界面简洁，同时保留功能可用性。**

### 隐藏什么

| 隐藏对象 | 说明 | 示例 |
|----------|------|------|
| **高级功能** | 普通用户用不到 | 专业模式、高级设置 |
| **不常用功能** | 偶尔使用的功能 | 导出、打印 |
| **个性化选项** | 因人而异的功能 | 主题设置、通知偏好 |
| **细节信息** | 需要时再看的信息 | 详细信息、技术参数 |

### 隐藏方式

| 方式 | 适用场景 | 示例 |
|------|----------|------|
| **折叠/展开** | 有明确标题的内容 | 常见问题FAQ |
| **标签页** | 不同类别的内容 | 商品详情/评价/参数 |
| **更多按钮** | 次要操作 | "更多"菜单 |
| **设置页面** | 个性化配置 | 系统设置 |
| **手势/快捷键** | 高级用户功能 | 长按菜单 |

### 隐藏的设计要点

1. **可见性线索**：让用户知道有隐藏内容
   - "展开更多"按钮
   - 滚动条提示
   - "..."省略号

2. **渐进披露**：按需提供详细信息
   - 先显示摘要，再显示详情
   - 先显示主要选项，再显示高级选项

3. **避免过度隐藏**：核心功能不应隐藏
   - 用户找不到的功能等于不存在
   - 平衡简洁性和可发现性

## 策略四：转移（Transfer）

### 核心原则

**将复杂性转移到最适合处理它的地方。**

### 转移方向

#### 1. 用户 → 系统

让系统承担复杂工作，用户只需简单操作。

| 场景 | 转移前 | 转移后 |
|------|--------|--------|
| 日期输入 | 手动输入格式 | 日期选择器 |
| 地址输入 | 手动输入全部 | 自动定位+补全 |
| 图片处理 | 手动调整参数 | 一键美化 |

#### 2. 系统 → 用户

让用户控制复杂功能，系统提供工具。

| 场景 | 说明 |
|------|------|
| 自定义排序 | 用户自己拖拽排序 |
| 自定义筛选 | 用户设置筛选条件 |
| 个性化推荐 | 用户标记兴趣偏好 |

#### 3. 设备间转移

利用不同设备的优势。

| 场景 | 手机端 | PC端 |
|------|--------|------|
| 内容消费 | 浏览、阅读 | - |
| 内容创作 | 简单编辑 | 复杂编辑 |
| 数据查看 | 查看概览 | 详细分析 |

#### 4. 现在 → 以后

将复杂决策推迟到必要时。

| 场景 | 立即要求 | 推迟到以后 |
|------|----------|------------|
| 注册流程 | 填写所有信息 | 先体验，后完善 |
| 权限申请 | 启动时申请所有权限 | 使用时再申请 |
| 复杂设置 | 首次使用就设置 | 提供默认，后续调整 |

### 转移的设计要点

1. **明确责任边界**：用户做什么，系统做什么
2. **提供默认选项**：减少用户决策负担
3. **允许自定义**：在默认基础上提供调整空间
4. **智能推荐**：基于数据预测用户需求

## 四策略的应用顺序

### 决策流程

```
面对复杂功能
    │
    ├─ 能删除吗？ ──→ 删除
    │     否
    │
    ├─ 能组织吗？ ──→ 组织
    │     否
    │
    ├─ 能隐藏吗？ ──→ 隐藏
    │     否
    │
    └─ 转移复杂性 ──→ 转移
```

### 组合使用

实际设计中，四个策略往往组合使用：

**示例：设置页面设计**

| 策略 | 应用 |
|------|------|
| 删除 | 移除极少使用的设置项 |
| 组织 | 将设置按功能分组（账号/通知/隐私） |
| 隐藏 | 高级设置折叠在"更多"中 |
| 转移 | 复杂配置转移到PC端完成 |

## 实践案例

### 案例：电商App商品详情页

| 策略 | 应用前 | 应用后 |
|------|--------|--------|
| **删除** | 显示所有商品参数 | 只显示核心参数，其他收起 |
| **组织** | 信息平铺 | 分块：基本信息/价格/规格/评价 |
| **隐藏** | 所有操作都显示 | 次要操作放入"更多" |
| **转移** | 复杂对比功能在App内 | 转移到PC端或专门工具 |

### 案例：表单设计

| 策略 | 应用 |
|------|------|
| **删除** | 删除可选字段，只保留必填 |
| **组织** | 按逻辑分组，分步填写 |
| **隐藏** | 高级选项默认折叠 |
| **转移** | 复杂验证自动完成，用户只需确认 |

## 检查清单

### 删除检查

- [ ] 列出了所有功能，标记使用率
- [ ] 删除了使用率<5%的功能
- [ ] 删除了重复的功能入口
- [ ] 删除了不必要的文字说明
- [ ] 删除了装饰性元素

### 组织检查

- [ ] 功能按逻辑分组
- [ ] 每组不超过7个选项
- [ ] 重要内容放在显眼位置
- [ ] 使用一致的布局模式
- [ ] 建立了清晰的层级关系

### 隐藏检查

- [ ] 识别了不常用功能
- [ ] 提供了隐藏内容的线索
- [ ] 核心功能没有被隐藏
- [ ] 隐藏的内容容易找到
- [ ] 渐进披露设计合理

### 转移检查

- [ ] 明确了用户和系统的分工
- [ ] 提供了合理的默认选项
- [ ] 复杂任务有简化路径
- [ ] 跨设备体验一致
- [ ] 推迟了非必要决策
